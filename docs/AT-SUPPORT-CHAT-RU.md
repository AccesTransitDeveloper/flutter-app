# AT Support Chat — клиентское приложение

Вкладка профиля (Account): пункт **AT Support Chat** сразу после **Settings**.
Существующие Help, Inbox и AI Assistant не заменяются.

Чат предназначен для переписки с живым диспетчером в AT-CRM. Используется тот же
интерфейс и обработка вложений, что в приложении водителя:

- сообщения и ответы диспетчера; обновление каждые 5 секунд, только на открытом экране;
- фото с камеры/галереи, защищённый просмотр фото и получение файлов;
- PDF, TXT, CSV, DOC/DOCX, XLS/XLSX, PPT/PPTX, ZIP, JPEG/PNG/WebP/GIF;
- до 3 файлов по 4 МиБ; фото уменьшаются до 2048 пикселей с качеством 85%;
- разовая отправка текущего местоположения после разрешения пользователя;
- черновики и копии файлов сохраняются в данных приложения отдельно по аккаунтам;
- стабильные UUID загрузок и сообщений сохраняются до сетевого запроса:
  после неоднозначного сбоя Retry повторяет исходное сообщение, не создаёт новое.

## Авторизация и CRM

Мобильное приложение обращается к защищённому шлюзу:

`https://fashnmall.com/at-driver-web/onboarding/api/passenger-support`

Шлюз проверяет мобильный Authorization через Core API
`https://api.accessibletransit.com/api/auth/get_entity_detail`.
Core проверяет токен, запись аккаунта и устройство из токена. Допустим только
клиентский тип **2**. ID, имя и телефон берутся из ответа Core, не из тела
запроса приложения. Необязательный `x-support-country` передаёт только код
страны для совместимости профиля Core и не определяет владельца чата.

CRM получает обращения в пространстве
`/api/external/support/passenger/{verifiedAccountId}/...`.
Чаты, файлы и прочтение клиентов отделены от пространства `driver`, даже если
ID аккаунтов одинаковые. CRM использует для сообщений клиента роль `user`;
приложение отображает их как свои, а `support_agent` — как ответ диспетчера.
Ключ CRM находится только на сервере. Авторизация клиента не передаётся CRM,
AI-ассистенту или в URL. Внутренние заметки CRM не показываются клиенту.

На стороне CRM требуется версия с приватными вложениями, подготовленная для
водительского AT Support Chat. Дополнительная публичная файловая служба не нужна.
Отправленные документы не объявляются проверенными или безопасными от вирусов.

## Выпуск и проверка

1. Опубликовать обновлённый Transit-Assistant-AI со шлюзом passenger-support.
2. Проверить, что AT-CRM опубликован с API приватных вложений.
3. Собрать новую версию flutter-app; сохранить существующие SDK/lockfile,
   подпись приложения, Firebase и настройки Mapbox.
4. Проверить полный обмен с диспетчером на Android/iOS с тестовыми файлами:
   фото, документы, координаты, отказ в разрешениях, перезапуск и повтор
   отправки после обрыва связи. Проверки виджетов не заменяют физические устройства.
